# 本地 ↔ Notion 同步

## 0. 启用条件
- 主人 2026-10-16 已在与图书馆的私聊里批准知识库同步 Notion，并随后把结构定为**数据库行模式**。
- 大文件、电子书、PDF **不传源文件**：读后把重要内容转为文字写入对应条目；转写完的源文件移入所在目录 `已转写/`，之后不再调用。
- **不转写**：千里命稿、星平会海、李虚中命书、滴天髓今注（扫描 PDF）。
- **先跳过**：`公孙羽家装宝典（已申请版权，盗卖必究）/`（主人之后单独处理）。
- 临时文件只放在 `E:\coding` 下，用完即删；不得在共用云电脑留存原文或隐私。
- 授权失效时找大管家；重新授权前先关 VPN（VPN 会拦本地回跳）。

## 1. 原则
- **本地为主（single source of truth）**：`E:\coding\知识库\` 是母本；Notion 是阅读与筛选视图。冲突时以本地为准；主人在 Notion 里改了内容，先回写本地再同步。
- 单向为主：本地 → Notion；Notion 评论只读回来作参考。

## 2. Notion 结构（主人规则 · 数据库）
- **一个知识数据库**；**每条知识占一行**（对应本地一篇 md）。
- 属性至少包括：
  - **类型**：专业 / 经验
  - **学科**
  - **标签**（多选）
  - **来源**
  - **关联**（关联其他行）
- 正文放在该行对应的页面内容里（或数据库正文属性，以实际 Notion 库设置为准）。
- 用**筛选视图**按类型、学科、标签浏览；**去掉大类页**；不把同学科多条知识合并进同一个页面。

## 3. 映射表
本地维护 `知识库/notion-映射.md`：
| 本地路径 | 类型 | Notion 行/页面 ID | 内容哈希 | 最后同步 |
|---|---|---|---|---|
- 路径移动或专业/经验拆分后，更新对应行；删除本地条目时不自动删 Notion，列清单问主人。

## 4. 增量同步流程
1. 列出本地专业 + 经验知识点，计算正文哈希（如 SHA-1），与映射表比对：新增 / 变更 / 未变。
2. **新增**：在数据库插入一行，填类型、学科、标签、来源、关联，写入正文。
3. **变更**：按映射表定位行，更新属性与正文。
4. **本地删除或移动**：不自动删 Notion，列清单问主人。
5. 写回映射表，更新时间用 UTC+8。

## 5. 格式转换
- frontmatter → 数据库属性（类型、学科、标签、来源、关联）；必要时在正文顶部保留一行摘要。
- `> 💡 …` → callout；`<details>` → toggle；`> 「…」——出处` → quote；表格 → table。
- 库内相对链接 → 指向对应数据库行的 mention；做不到就写「见『标题』」。
- 外链保留；图片需上传后替换（优先不传大图源文件，能转述则转述）。
- 使用 MCP `user-Notion` 相关工具，调用前先看工具 schema。

## 6. 校验
- 同步后抽查 2 条：属性齐全、筛选视图能找到、正文表格/引用可读；在当日 21:00 汇报里写同步了几条。
