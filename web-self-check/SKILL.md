# 网页自检（Web Self-Check）

写完代码 ≠ 做完网页。每次网页产出后走「截图 → 判分 → 不合格自动改」的闭环。

## 何时执行

- 新建或修改了任何用户可见的网页后，交付前必跑一次。
- 用户明确要求视觉/交互验收时。
- 修 bug 类的小改动只需复查受影响区域，不必全量。

## 工具

按 `webapp-testing` skill（`e:/coding/.cursor/skills/webapp-testing/`）的方式起服务和写 Playwright 脚本：

- 静态 HTML：直接 `file://` 打开或起简单 http server。
- 动态应用：用 `with_server.py` 管理服务生命周期。
- 截图后**必须用读图工具真的看图**，不能只靠 DOM 断言。

## 验收流程

```
产出网页
  → 起服务/打开页面，等 networkidle
  → 三个视口截图：375px（手机）/ 768px（平板）/ 1440px（桌面）
  → 读图 + 交互检查，对照下方清单逐条判定
  → 全部通过 → 汇报截图与结论，结束
  → 有不通过项 → 列出问题清单 → 自动修改 → 回到截图步骤
  → 第 3 轮仍不通过 → 停下，带截图向用户汇报卡点，请用户决策
```

自动修改轮次上限：**3 轮**。超限说明问题不是机械改法能解决的，不要死循环。

## 验收清单（草案，待补充）

### 视觉

- [ ] 三个视口下无横向滚动条、无内容溢出/截断、无元素重叠
- [ ] 图片/媒体正常加载，无裂图占位符
- [ ] 正文对比度可读（深底浅字/浅底深字，不出现灰底灰字）
- [ ] 间距节奏一致：同级元素的 margin/padding 不忽大忽小
- [ ] 字号层级清晰：标题/正文/辅助文字至少三级可辨
- [ ] 首屏没有明显空白或「只有一半内容」的断裂感

### 交互

- [ ] 所有导航链接、按钮可点击且指向正确（无 404、无死链接）
- [ ] hover/focus 有可见反馈（至少不出现指针变了样式不变）
- [ ] 表单能提交，必填校验生效，错误提示可见
- [ ] 键盘 Tab 可以走完主要交互路径
- [ ] 浏览器 console 无红色报错（警告可记录不阻塞）

### 移动端

- [ ] 375px 下点击目标不小于约 44px，文字不需要缩放就能读
- [ ] 固定定位元素（导航、悬浮按钮）不遮挡正文

## 汇报格式

每轮验收后输出：

1. 三张截图（内嵌展示）
2. 清单判定：通过 N 项 / 不通过 M 项，逐条列不通过原因
3. 若进入下一轮：本轮准备改什么

## 与 auto-iterate 的关系

- 本 skill 管**客观合格线**（清单判定，agent 自己闭环）。
- `auto-iterate` 管**主观方向**（三轮人工修改后问用户三个问题）。
- 两者可同时生效：清单不过 → 自动改；清单过了但用户仍连改三轮 → auto-iterate 接管问方向。
